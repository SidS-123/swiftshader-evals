(formats × sizes × modes), not how much implementation work it takes.

with this table as one input and the case counts in §11.1 as the other.

## 3.4 Determinism — done in Stage 4: see determinism.md

It needs a replay driver. The plan allows running this after the minimal
`vkreplay` exists. Hypotheses to test, from the source reading:
atomics ordering, float reductions across threads, timestamps and pipeline
statistics vary, and transcendental approximations differ between LLVM and
Subzero. Additional hypothesis, unverified: Reactor emits code for the
**host CPU's** features (SSE4.1/AVX, etc.), so float results could differ on
another CPU. The reference caches and grading must therefore run on the same
host, or the effect has to be measured on a second CPU before anyone claims
cross-host reproducibility.

## 3.6 lavapipe vs SwiftShader (fairness note)

- Extensions: lavapipe 179, SwiftShader 85, 80 in common. The 5 only in
  SwiftShader are swapchain ones plus `VK_KHR_internally_synchronized_queues`.
- Features: 64 of 164 SwiftShader values differ; properties: 87 of 143 differ,
  mostly limits (descriptor counts, alignments 256 vs 16, work group sizes,
  8x MSAA, tessellation/geometry present on lavapipe).
- Same raster/texture precision bits (8/8/6), `strictLines`, and standard
  sample locations. **Subgroup size differs: 8 vs 4**, so subgroup cases
  score differently on lavapipe unless written size-independently.
- Expectation: lavapipe scores low on procedural `profile_match` and limits
  checks by construction. Its replay score is the interesting number: how
  much of "correct Vulkan" matches SwiftShader's pixels.
